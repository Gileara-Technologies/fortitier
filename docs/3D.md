# 3D experience — Fortitier

The homepage is **The Haul**: one continuous, scroll-driven WebGL world in the manner of igloo.inc.
Scrolling *is* one tanker trip. Everything is procedural (no model, texture or HDR downloads); the only
image the scene reads is the brand icon in `public/brand/`, sampled for the finale particles.

Skills applied: `3d-web-experience`, `premium-3d-website`, `scroll-3d-world` (one camera spine, chapter
dwell, debug hook, QA the flight), `design-taste-frontend`.

## Architecture

| File | Role |
|------|------|
| `src/components/experience/story.ts` | Single source: chapters (weights, copy, readouts), world layout, and `tripAt(p)`, the pure trip state for any scroll progress. The scene and the HUD both read it, so they always agree. Unit-tested in `tests/story.test.ts`. |
| `experience/Experience.tsx` | DOM shell: tall section + sticky viewport, Lenis smooth scroll, preloader, scrambled chapter titles, telemetry HUD, chapter rail, opt-in sound, reduced-motion version. |
| `experience/HaulScene.tsx` | Canvas root: lights, environment, post-processing, `Director` (camera), callouts, shader precompile (`Ready`). |
| `experience/HaulTanker.tsx` | Procedural tractor-trailer tanker driven by a mutable state ref: `speed`, `fill[3]`, `xray`, `explode`. |
| `experience/World.tsx` | Sky, dot-matrix terrain, road, streetlights, depot gantry + tank farm, filling station + underground tank, reconcile columns, dust, logo particles. |
| `experience/engineSound.ts` | Procedural diesel + road noise (Web Audio), opt-in only. |
| `experience/ScrambleText.tsx` | Instrument-style title reveal; real text stays in an sr-only span. |

## Chapters (one flight)

`hero` gantry → `load` x-ray fill → `track` highway + crane-up → `inspect` exploded view with leader
lines → `deliver` station, hose, underground tank → `reconcile` loaded/delivered columns balance →
`finale` particle F + CTA. Weights in `story.ts` set how much scroll each consumes.

## Rules

- **One smoothing stage.** `Director` damps scroll progress with frame-rate-independent exponential
  smoothing; the camera is then placed exactly on `poseFor(chapter, t, truckX)`. Never add a second
  lerp on the camera: at low frame rates it trails the moving truck and frames go empty.
- **Camera before labels.** Camera rigs run at `useFrame` priority `-1` so `Label3D` projects through
  the current frame's camera.
- **Labels.** In-scene text uses `Label3D` (+ optional `leader` line) from `three/SceneShell.tsx`, a
  plain DOM overlay. Never drei `<Html>` (nested React roots tear down empty under React 19).
- **Tone mapping.** The composer renders to targets, so the renderer's tone mapping is bypassed; the
  `ToneMapping` (ACES) effect at the end of `Effects` is required for real blacks.
- **Preloader.** Rendering is held off (`frameloop: never`) while `compileAsync` compiles every shader;
  the counter is time-based so a busy main thread cannot stall it.
- **Off-screen.** The sticky canvas is always "visible" to an IntersectionObserver, so `active` (set
  from the section's own observer) switches its frameloop off once you scroll past the experience.
- **Reduced motion.** No pinned flight, no Lenis: a static hero frame plus every chapter as plain text.
- **No WebGL.** `SceneFallback`; all copy, telemetry and CTAs are DOM.
- **Honesty.** Telemetry and litres are a labeled `SIMULATION`; GPS readout interpolates Tema → Kumasi
  for illustration only.

## QA hooks

- `window.__haul` (read-only): `{ p, target, chapter, t, settled, calls, triangles, points, dpr }`.
  Automated captures must wait for `|target − requested| < 0.002 && settled` before screenshotting;
  polling with fixed timeouts captures stale frames.
- `?off=effects,terrain,dust,env,lights,street,depot,station,truck` drops subsystems for profiling.

## Measured (Intel Iris Xe, 1440×900, DPR 1)

Steady 41–61 fps across all chapters; ~340 draw calls, ~50k triangles, ~73k terrain points; first
load route 146 kB with the 3D chunk lazy-loaded behind the preloader. Heaviest: `load` (transparent
shell + liquids).

## Swapping in a real tanker model

Place a GLB under `public/models/`, compress with
`gltf-transform optimize in.glb out.glb --compress draco --texture-compress webp`, and keep the
`TankerState` contract (`speed`, `fill`, `xray`, `explode`) so the story keeps driving it.
